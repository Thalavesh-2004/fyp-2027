💡 Understanding the Metrics

Records Attacked = how many individual events were corrupted (e.g. 1,021 out of 10,000 = ~10%). Sensors Wrong = how many per-sensor aggregates (avg temperature) failed ground-truth validation. Even 5% record corruption poisons ALL 5 sensor averages because each corrupted record shifts the aggregate by +50°C ÷ total records — exceeding the ±0.01°C validation tolerance.

Detailed Experiment Results

Per-experiment output metrics showing the impact of each Byzantine attack mode. Note: "Records Attacked" shows individual corrupted events, while "Sensors Wrong" shows how many per-sensor aggregates failed ground-truth validation.

⚠️ Amplification Effect

Even when only 5-10% of individual records are corrupted (+50°C each), all 5 sensor aggregates become incorrect. This is because each corrupted record shifts the average temperature by (corrupted_count × 50) ÷ total_count, which far exceeds the ±0.01°C validation tolerance. This "amplification effect" is a key research finding — a small number of Byzantine records can poison an entire aggregate computation.

Independent Ground Truth Validation

Expected aggregate statistics computed independently from the raw input events (without going through Spark). These values are compared against Spark's output to detect Byzantine corruption.

✅ How Ground Truth Works

The Ground Truth Calculator processes the same raw events using pure Python — completely independent of the Spark streaming engine. It computes per-sensor averages, min/max, and counts. Then the Comparator checks if Spark's output matches within a tolerance of ±0.01. Any deviation is flagged as corruption.

Key Research Findings

Critical observations from the September 2026 experimental demonstration.

🔴 Finding 1: Spark Silently Accepts Corrupted Results

In all value corruption experiments (5% – 50%), Apache Spark reported TASK SUCCESS for every micro-batch. The Byzantine worker remained active, returned manipulated temperature values (+50°C), and Spark's built-in fault tolerance (lineage + checkpointing) never triggered a retry. Standard Spark assumes fail-stop behavior and has zero protection against semantic corruption.

🔴 Finding 2: Even 5% Attack Rate Corrupts 100% of Aggregates

With only 5% of individual records attacked, all 5 sensor aggregates were detected as incorrect by the Ground Truth Validator. Because aggregation functions (avg, min, max) combine values across many records, even a small fraction of corrupted inputs poisons the entire output.

🔵 Finding 3: Delay Attacks Degrade Throughput by 4x

The 20% delay attack (500ms per affected batch) reduced throughput from ~70,000 rec/s down to ~16,000 rec/s and increased average latency from 4.3ms to 105.6ms — a 25x latency increase. However, unlike value corruption, delay attacks did not affect result correctness (100% accuracy maintained).

🟢 Finding 4: Independent Ground Truth Validation Works

The dual-computation architecture successfully detected every instance of Byzantine corruption. By maintaining an independent calculation path outside of Spark's execution, the Ground Truth Validator achieved 100% attack detection rate across all experiments.

🔵 Conclusion: The Need for Trust Management

These results conclusively demonstrate that standard Spark fault tolerance is insufficient for Byzantine environments. The next research phase (October 2026) will implement an Adaptive Verification Module and Trust Management System to automatically detect, isolate, and remediate untrustworthy workers in real-time.
